### R-01 workspace 骨架和风险验证
- 建 workspace 和三个 crate(`01`「分层」),profile 照 `01`。`.gitignore` 忽略 `target/`。
- `xredis-gpui` 用 `gpui-kit = "=0.9.1"` 开一个窗口:标题 `xRedis v{CARGO_PKG_VERSION}`,最小 1024×840,默认 1600×903。
- `xredis-core`、`xredis-app` 先放空模块和一个能跑的测试。
- `scripts/test-redis.sh`:`start` 起容器 `xredis-test-redis`(`redis:8`,只绑 `127.0.0.1:6391`,带密码,密码只在脚本和环境变量里,不写进提交以外的地方)、`stop`、`test [cargo 参数]`(起容器、设环境变量 `XREDIS_TEST_REDIS_URL`、跑 `cargo test -- --ignored`,带超时)。不碰 6380 等其他容器。
- **风险验证**(结论写进日志,有问题立即停下报给架构师):
  1. gpui-kit 0.9.1 在 Windows 上能编译、能跑;记下首次全量编译时间、`target/` 大小。
  2. 中文、日文、emoji 能显示(key 名常有中文);中文输入法能在 Input 里输入。
  3. gpui-component 有没有:虚拟滚动的 Table、多行代码编辑器(语法高亮支持哪些语言、能否只读)、Select、Dialog、Tabs、Notification、文件对话框(或 GPUI 自带的 `prompt_for_paths`)、剪贴板读写。列出缺的。
  4. GPUI 的测试支持(`TestAppContext`)能否通过 gpui-kit 用上。
  5. 空窗口发布版的空闲内存(工作集)和 exe 体积。
- 完成标准:`cargo build`、`cargo test --workspace`、clippy 通过;窗口能开;日志写清 5 项结论。
